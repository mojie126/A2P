# 官方 beta 同步与 WASM 改进吸收记录（2026-11-19）

本文记录本轮（2026-11-19）同步官方 v3.5.0-beta.2 与 beta 分支后续提交的过程与结论：官方 beta.2 把全部提供商重写为独立 WASM 插件（`wasm/`，38 个目录），本仓库决定不迁移 WASM 架构，把官方改进吸收回原生实现（`crates/providers/`）。

## 官方基线增量

- 2026-11-18（`694d5d9`，tag `v3.5.0-beta.2`）：全部提供商拆分独立 WASM 插件（官方 CI 只批量构建 `wasm/*/pack.json`，`crates/providers` 原生实现保留但不再构建发布），新增百度搭子 DuMate、科搭 Codar 独立插件，Kiro、AutoClaw、Cline、小浣熊补齐本机凭据续期与安全写回，AtomCode 对接新版套餐状态，千问办公保留企业凭据，Qoder 国际版 UMID 校验组件，豆包工作、库库、Loomy、ZCode 原生侧修复；1023 个文件，新增 14.2 万行
- 2026-11-19（beta 分支，`d65247f`、`b72f882`、`ab6432d`、`c602fc5`、`d56f625`）：独立插件 `0.1.0-beta.2` 发布（CodeArts、WorkBuddy 国内版、WorkBuddy 国际版、Trae）；Trae 逐包读数缺失回退官方积分汇总、WorkBuddy 分片正文通道与凭据地区识别、CodeArts stop 参数清理与华为网关错误码识别；此批提交对 `crates/` 无改动，全部在 `wasm/` 侧
- 主仓库（aimod-cc/Agent2API）同期发布 `v3.5.0-beta.3`（`cd0411bf`），与插件侧 `8e83ecb5` 余额列修复同源

## 不移植判定（留档防重复调查）

| 官方改动 | 判定理由 |
| --- | --- |
| WorkBuddy 端点白名单（仅 4 个官方域） | 白名单是 WASM 沙箱 origins 声明的安全机制；原生注释明确保留自建网关场景（`endpoint` 可显式覆盖，`workbuddy_shared/endpoints.rs`），照搬会砍本地功能 |
| Trae 工具完整性校验（Done 时 flush_tools） | 官方依托整包重发架构（WASM 侧自己产出帧序列），原生逐 delta 透传只能事后标记无法拦截已发片段，轻量版误报风险高 |
| qoder 设备标识按地区拆分（四站点四文件）、按账号持久化 | 本地 `machine.rs` 注释明确记录两地区共用是历史行为（改文件名会动已发布账号的设备指纹，上游按设备聚合限流）；per-account 同理 |
| qoder UMID 组件严格本 variant（不跨 variant 回落） | 原生跨 variant 回落是对齐参考实现（CreditDaddy `apps.find || apps[0]`）的有意设计；官方收紧是沙箱无文件系统访问的约束产物 |
| raccoon 续期预约持久化（reserve/complete） | 原生已有比较写回保护（`apply_refresh` 三种结局）与单飞；崩溃窗口后旧 refresh_token 重试必然 401，结局与预约后 409 等价，复杂度不划算 |
| qwenwork 设备文件授权门（helper 权限） | `native_call` 授权门是 wasm.json 能力声明机制，原生无对应沙箱模型 |
| qwenwork 手工导入登录入口 | 原生「粘贴完整账号记录」路径（`from_payload`）已等价覆盖 |
| AtomCode 网关 HMAC 签名 | 原生刻意走免签网关 `api-ai.gitcode.com`（`endpoints.rs` 实测，签名门由 UA 触发） |
| WorkBuddy 分片正文通道（64 KiB 分片、128 MiB 上限） | `b72f882` 的内存上限与分片是 WASM 实例内存限制的产物，原生进程内无此约束 |
| cline 拆分三目录（common/free/pass） | 原生已按池参数化（`Pool::Free/Pass`），无需拆目录 |
| catpaw、monkeycode、codearts 对话链路对齐 | 均为「原生 → WASM」搬运（wasm 目录全部文件是 beta.2 新增），原生已对齐或更强（codearts 福利含 Skill 创新赛报名礼等本地增强） |

## 待办与待确认

- dumate quota `ignoreLoginBonus=true` 参数：官方口径把登录赠送积分从余额读数中扣除，会改变现有账号余额展示，与本地用量口径修复可能冲突，待确认意图
- dumate 新功能吸收（文生图 `images.rs`、积分流水明细 `/points/records`、活动只读预览 `activities.rs`）：官方有、本地无的新功能面，需对接 Provider 图片接口与 admin 面
- autoclaw 在途保护与节流（`inFlightUntil` 不被巡检抹掉、每小时节流）：原生「刷新不写回文件，只进进程缓存」架构下竞态面不同，需单独调查
- 主仓库 `v3.5.0-beta.2` / `v3.5.0-beta.3` 的跟进现状与待办分类见 A2API 仓库 `docs/官方beta跟进清单_2026-11-19.md`

### 追加吸收的改进

- Trae：逐包读数缺失时回退上游 `usage_summary` 剩余积分（`d65247f`），避免把 SOLO 并发数当余额
- CodeArts：对话转发前移除 `stop` 字段（`ab6432d`），并补全华为网关复合业务码末段到状态码的映射与业务码展示

### 本批结论

- dumate 的 `ignoreLoginBonus=true` 不采用：登录赠送积分仍可用于对话，扣除会低估可用积分；本家以 `totalPoints - usedPoints` 展示总的可用积分
- dumate 用完（剩余为 0）的积分包按最终口径在所有位置排除，不在余额、明细或额度详情中展示
- dumate 新功能只实现只读的积分流水与活动/抽奖状态查询（`admin_action` 的 `usage.records`、`usage.charge_records`、`activity.tasks`、`activity.draw_status`）；文生图依赖主仓库的异步出图轮询支持（`ImageResponseKind`），且官方自述未完成真实账号验收，暂不实施
- autoclaw 的在途保护不移植：原生已有单飞刷新表、比较写回与每小时强制刷新节流（`credentials.rs` 的 `hourly_forced_refresh_due`），官方 `inFlightUntil` 持久化在「刷新不落盘」架构下的崩溃结局与原生等价
- 工作流版本基线：插件仓库 `dev-build.yml` 增加 pack.json 与 Cargo 版本一致性校验，发布说明按版本号推导并支持缺失回退；主仓库 `fork-build.yml` 同口径改为动态生成发布说明，避免版本升级后因文件名不同步导致发布失败

### 新增私有修复

- 清理三处 `expect`（codearts/officeace 的 HMAC 构造、dumate 的固定时区与零点计算），满足 crates 级 `deny(unwrap_used, expect_used, panic)`，release 零 panic 约定得以守住


## 第三批（同日追加）

### 云同步与限额台账

- `cloud_sync/snapshot.rs` 的同步表移除 `account_limiter_events`：该表按请求逐条累积，只服务本机近期窗口判定，换机后没有展示价值，是同步包体积增长的主要来源；旧快照里仍带该表时按「不在同步范围」忽略，不覆盖本机
- 新增限额事件历史修剪：`limiter::prune_history` 删除 30 天前的记录，由调度循环在启动时执行一次、之后每 24 小时一次；数据库未就绪时下一轮重试。同步包与本机数据库都不再随运行时间无限增长

### DeepAI Code 能力补齐

- Responses 通道：目录保留 `api = openai-responses` 的模型（如 `gpt-6-astra`），对话统一走 `conversation`；Responses SSE 翻成 chat 帧（文本、思考、工具调用、用量）
- 联网搜索：`admin_action` 的 `web-search.capabilities` 与 `web-search.search`，调用 `/deepai_code/web_search`（请求体 `{query, num_results}`），结果按常见形状宽容解析为 `sources`
- 浏览器授权登录：打开 `desktop_auth` 地址，插件在本机随机端口接收回调并用 `code` 换取 API Key；服务端部署可用 `login.callback` 回填回调地址
- 复用共享 `responses` 模块（`crates/providers/src/responses.rs`），实现体仍取自 AStudio 的 Responses 转换

### 科搭能力补齐

- 微信扫码登录：申请二维码后用宿主浏览器打开，按 `login.poll` 轮询扫码状态，成功后核对资料并落账号
- 本机关联：只读 `~/.codar/config.json`（`CODAR_HOME` 可覆盖）的当前登录令牌，不写回客户端文件；续期时重读该文件
- Anthropic 与 Responses 协议：目录保留三种协议的模型，对话统一走 `conversation`，按模型协议构造请求并把上游事件翻成 chat 帧
- 活动领取：`admin_action` 的 `activities.preview`、`activities.claim`、`activities.mine`，领取后回查，结果不明时十分钟内不重复提交
- 手机验证码登录：原生入口提供两段式路径——`admin_action` 的 `auth.sms.send` 在完成阿里云人机验证后发送验证码，随后用 `sms:手机号:验证码` 作为访问令牌导入；面板内的交互式表单链路需要网关对原生插件开放 `login.interaction.v1`，当前只对 WASM 插件开放
- 登录方式元数据按网关 `LoginMethodMetadata` 契约修正：提示项类型只使用 `text` 与 `select`、补齐 `label`，本机读取方式改用 `oauth + localOnly`（`api + localOnly` 会被网关拒绝）；本机读取方式在登录对话框里点一下即完成
- 提供商图标在网关面板维护：`ui-shared/provider-icons.ts` 增加 `deepaicode` 与 `codar` 两个映射，资源放在 `ui/assets/providers/`（科搭取自官方插件资源，DeepAI 使用参考仓库的图标）
- 出网代理修正：两家新提供商的额度、目录、签到、搜索、登录换码与本机验活统一遵循「账号代理 → 网关代理 → 直连」；登录阶段还没有账号记录，代理取自登录对话框选项（`login.start` 的 `proxy`），登录流程内按流程保存并在回调换码、扫码轮询与资料核对时复用。此前添加账号与 OAuth 换码忽略该代理，在必须经代理出网的环境里表现为「连接上游超时」
- 端到端验证：直接对插件二进制调用 `account.normalize` 并传入本机代理，两家都到达上游并返回业务错误（DeepAI 401、科搭 401），不再是连接超时；科搭 `login.start` 经代理成功返回真实二维码地址
- 模型计费：DeepAI 目录按 `theosPerRequest` 生成 `credits` 文案（`免费` 或 `N Theos/次`），模型页的计费列直接展示；科搭目录的 `rate_badge` 与 `pricing`（人民币 / 百万 tokens）已解析，静态快照按 2026-11-19 实时目录刷新为 20 个模型并带上倍率与价格
- 科搭扫码：补齐终态识别——手机绑定或新 IP 验证（`bind_phone_required` / `ip_verify_required` / 业务码 201）提示改用官方客户端登录后「读取本机登录态」或「粘贴访问令牌」；过期、取消、被拒绝分别给出明确文案，并带上未知状态原文
- 科搭扫码轮询改为跟随上游长轮询：状态请求超时从 8 秒放宽到 65 秒，避免客户端反复中止长轮询导致扫码结果丢失；HTTP 或业务码 404 统一提示「二维码已失效或登录场景已过期」
- 科搭账号资料接口迁移：`/api/user/self` 实际在业务域名 `api.claw.speedai.com`，账号域名 `api.kuaipaper.com` 对该路径返回 404；导入令牌与扫码后的资料核对改用业务域名（2026-11-19 用真实令牌实测确认），其余积分、签到、扫码、续期接口仍在账号域名

## 跟进边界（结论）

官方 beta.2 与 beta 后续提交对本仓库只有两部分值得吸收，其余为 WASM 沙箱架构的产物，原生体系下无对应实现或已被本地覆盖：

- **已吸收**：官方 `crates/` 的 18 个文件修复、9 项 WASM 侧行为改进、`d65247f` 与 `ab6432d` 两项后续修复（对应移植见上文）
- **不吸收**：WASM 插件目录、宿主 `native_call` 授权门、沙箱内存上限衍生的分片通道等（判定见上文「不移植判定」表）
- **剩余待办**：见上文「待办与待确认」，均为需要产品口径确认或依赖主仓库新接口的项目
